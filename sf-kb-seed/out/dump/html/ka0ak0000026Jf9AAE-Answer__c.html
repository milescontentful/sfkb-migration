Idempotency Key Validity Window

Every idempotency key you include in a Brightline Partner API request is stored in our deduplication cache for exactly 24 hours from the moment the request first reaches our servers. During that window, any repeat call using the identical key and endpoint will receive the original cached response—including the original HTTP status code, response body, and X-Brightline-Request-Id header—without triggering a second operation.

What Happens After 24 Hours

Once the 24-hour window closes, the key is purged from the cache. If you submit a new request using that same key after expiry, the API treats it as a brand-new request and executes the operation again. This can result in duplicate records or charges, so you should generate a fresh key for any intentional retry after the window has lapsed.

Key Format Requirements

  • Must be sent in the Idempotency-Key request header.
  • Maximum length: 128 characters.
  • Accepted format: UUID v4 (recommended) or any URL-safe alphanumeric string.
  • Keys are scoped per OAuth2 client ID—the same string used by two different clients does not conflict.

Checking Cache Status

If you need to confirm whether a key is still cached, inspect the response header X-Brightline-Idempotency-Status. A value of replayed confirms you received a cached result; original means the request was processed fresh.
