Released: April 14, 2026 — API version 2026-04

Integrators can now consume temperature warning alert data in two ways:

MethodEndpoint / EventPolling Required
RESTGET /v2/sites/{site_id}/alerts/temperatureYes (pull)
Webhookalert.temperature.cautionNo (push)
Webhookalert.temperature.criticalNo (push)

Each webhook payload includes site_id, component (panel or battery), severity, measured_temp_f, threshold_temp_f, and triggered_at in ISO 8601 format.

The REST endpoint supports cursor-based pagination and returns up to 100 alert records per page. Requests that exceed rate limits return HTTP 429; see what error code 429 means for retry guidance.

Webhook subscriptions can be registered or updated via POST /v2/webhooks. Deliveries that fail to receive an HTTP 200 acknowledgment within 10 seconds are retried with exponential back-off for up to 24 hours. Authentication follows existing OAuth2 client-credentials flow; no credential changes are required for current partners.
