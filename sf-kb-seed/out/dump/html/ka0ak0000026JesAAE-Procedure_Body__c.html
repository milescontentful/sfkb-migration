Prerequisites: You must hold a valid OAuth2 access token with the reports:read scope. Your application must be approved for the Lifetime aggregation tier in the Brightline Developer Portal (Portal > App Settings > Data Access > Aggregation Tiers). Accounts without this tier approved will receive a 403 TIER_NOT_AUTHORIZED response. Refer to your token management workflow before proceeding; see Partner API OAuth2 Token Lifetime and Error Handling Update (October 2025) for current token expiry rules.

  1. Construct a GET request to https://api.brightlinesolar.io/v2/reports/production.
  2. Set the Authorization header to Bearer <your_access_token>.
  3. Add the query parameter period=lifetime. Optionally add system_id=<id> to scope the request to a single system; omit it to return all systems your token is authorized to access.
  4. Send the request. A successful response returns HTTP 200 with a JSON body containing total_kwh, co2_offset_lbs, estimated_savings_usd, data_start_date, and data_end_date fields.
  5. If you need a breakdown by year, append the query parameter granularity=yearly. The response will include a periods array with one object per calendar year.
  6. Cache responses on your side for at least 1 hour. Lifetime totals update once every 6 hours on Brightline's side; polling more frequently wastes quota and may trigger rate limiting.
  7. For bulk requests covering more than 500 systems, use pagination: include page=1&page_size=500 and iterate using the next_cursor field returned in the response envelope.

Troubleshooting

HTTP 429 Too Many Requests: You have exceeded the Reports endpoint rate limit of 120 requests per minute per application. Implement exponential backoff and honor the Retry-After header. See What does error code 429 mean in the Partner API for detailed guidance.

Empty total_kwh value (returns 0 or null): The system's PTO date is not yet recorded, or the system has no meter readings older than 24 hours. Verify the system status using GET /v2/systems/{system_id}/status before retrying.

HTTP 503 or intermittent failures: The Reports service may be under maintenance. Check the Brightline API Status page and review retry strategies at How do I troubleshoot 5xx errors in the Partner API.

Mismatched totals vs. app: Confirm your token's authorized system list matches the customer's account. Discrepancies of under 2% are expected due to rounding; larger gaps should be reported to Brightline Partner Support with the response's request_id value.
