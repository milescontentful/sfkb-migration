Prerequisites: Your application must have a registered webhook endpoint in the Developer Portal and an OAuth2 token with the read:events scope. This procedure covers the GET /v2/webhooks/events endpoint, which uses offset-based (not cursor-based) pagination because the event log is immutable and time-ordered. Use this workflow only to recover missed events; do not use it as a substitute for real-time delivery.

  1. Identify the time window you need to backfill. Note the UTC timestamp of the last successfully processed event stored in your system; you will use this as your starting boundary.
  2. Make an initial request to GET /v2/webhooks/events with the following query parameters: after (ISO 8601 UTC timestamp of your last processed event), before (current UTC time or desired end boundary), and limit (integer, 1–200; default 50). Example: GET /v2/webhooks/events?after=2026-03-01T00:00:00Z&before=2026-03-02T00:00:00Z&limit=200.
  3. The response includes a top-level meta object with total, offset, and limit fields, plus a data array of event objects each containing an event_id, event_type, delivered_at, and payload.
  4. Process all events in the data array in ascending delivered_at order to preserve event sequence. Record the highest delivered_at value you successfully process.
  5. If offset + limit < total, increment your next request's offset parameter by the value of limit. Example: add &offset=200 to fetch the next page.
  6. Repeat steps 4–5 until offset + limit >= total. Resume normal webhook delivery once backfill is complete.

Troubleshooting

Error INVALID_TIME_RANGE (HTTP 422): The after value is later than before, or the window exceeds 30 days. Narrow your time range to 30 days or less per request and chain multiple requests for longer outages.

Error SCOPE_INSUFFICIENT (HTTP 403): Your token is missing the read:events scope. Re-authorize your application in the Developer Portal under Apps > Your App > Edit Scopes.

Missing events in backfill window: The event log retains records for 90 days. Events older than 90 days are permanently purged and cannot be recovered via this endpoint.

SDK helpers: The official SDKs include a backfill_events() convenience method that handles offset incrementing automatically. Upgrade to the latest SDK version before using it; see Partner API SDK v2 Breaking Changes – March 2026 for migration notes.
