What Is an Idempotency Key?

An idempotency key is a unique string you generate and attach to a Partner API request so that Brightline's servers can recognize a retry of the same operation and return the original result instead of executing the action a second time. If your network request times out or drops before you receive a response, you can safely resend the exact same request with the same key and know it will not be processed twice.

When Is It Required?

Idempotency keys are mandatory on all requests that create or modify state. This includes:

  • Payment and billing operations (POST /v2/payments)
  • Webhook subscription creation (POST /v2/webhooks)
  • Battery dispatch commands (POST /v2/devices/{deviceId}/dispatch)
  • Report schedule creation (POST /v2/report-schedules)

Read-only GET requests do not require an idempotency key because fetching data is already safe to repeat.

What Happens If I Omit It?

The API returns HTTP 400 with error code IDEMPOTENCY_KEY_MISSING and the message: "A valid Idempotency-Key header is required for this request." The request is rejected and no action is taken.

Key Format Requirements

Keys must be 8–128 characters, containing only alphanumeric characters, hyphens, or underscores. UUIDs (v4) are the recommended format. Keys expire from Brightline's deduplication store after 72 hours.
