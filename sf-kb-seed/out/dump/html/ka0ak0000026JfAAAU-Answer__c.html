Required vs. Optional vs. Unsupported

The Brightline Partner API enforces a straightforward rule: idempotency keys are required on all endpoints that create or modify data, optional-but-recommended on certain async trigger endpoints, and silently ignored on pure read operations.

MethodExample EndpointKey Required?
POST/v2/paymentsYes — 400 error if omitted
POST/v2/alerts/acknowledgeYes — 400 error if omitted
POST/v2/reports/scheduleRecommended (optional)
PATCH/v2/batteries/{id}/modeYes — 400 error if omitted
DELETE/v2/webhooks/{id}Yes — 400 error if omitted
GET/v2/production/lifetimeNot supported (ignored)

Error Code for Missing Keys

If you omit an idempotency key on a required endpoint, the API returns HTTP 400 with error code ERR_IDEMPOTENCY_KEY_MISSING in the response body. No operation is performed.

Conflict Errors

If you reuse a key on a different endpoint or with a different request body, you will receive HTTP 409 with error code ERR_IDEMPOTENCY_KEY_CONFLICT. Always pair a unique key with a unique logical operation.
