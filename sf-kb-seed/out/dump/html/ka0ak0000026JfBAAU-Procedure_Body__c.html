Prerequisites: You must have an active Brightline Partner account with API credentials issued from the Partner Developer Portal (portal.brightlinesolar.dev). You will need your client_id, client_secret, and the list of OAuth2 scopes your application requested at onboarding. If you are using the official SDK, ensure you are on version 2.x or later (see Partner API SDK v2 Breaking Changes – March 2026).

  1. Identify the error code. Every authentication failure returns a JSON body with an error field. Common values are OAUTH_TOKEN_EXPIRED, OAUTH_INVALID_CLIENT, OAUTH_SCOPE_INSUFFICIENT, and OAUTH_TOKEN_REVOKED. Note the HTTP status code alongside it (typically 401 or 403).
  2. Check token expiry (OAUTH_TOKEN_EXPIRED). Access tokens issued by the Brightline authorization server are valid for 3,600 seconds (1 hour). If your integration does not cache and refresh tokens proactively, request a new token using the client_credentials grant before the current token expires. The token response includes an expires_in field you should track.
  3. Verify client credentials (OAUTH_INVALID_CLIENT). Log in to the Partner Developer Portal, navigate to Settings > API Credentials, and confirm that the client_id and client_secret in your environment match exactly. Secrets are case-sensitive and must not contain leading or trailing whitespace.
  4. Confirm scopes (OAUTH_SCOPE_INSUFFICIENT). The endpoint you are calling may require a scope your application was not granted. In the Portal, go to Settings > API Credentials > Manage Scopes and compare your granted scopes against the endpoint's documentation. Submit a scope expansion request from that same page; approval typically takes 1–2 business days.
  5. Handle a revoked token (OAUTH_TOKEN_REVOKED). Tokens are revoked when a partner account is suspended, a secret is rotated, or a security event is detected. Rotating your secret in the Portal automatically invalidates all existing tokens. Generate a new secret, update your environment variables, and request a fresh token.
  6. Test with a raw HTTP request. To isolate whether the error is in your SDK or your credentials, send a direct POST to https://auth.brightlinesolar.dev/oauth2/token with the Content-Type: application/x-www-form-urlencoded header and your credentials. A successful response returns 200 OK with an access_token.
  7. Retry your original request. Attach the new token in the Authorization: Bearer <token> header and confirm you receive a 200 or 202 response.

Troubleshooting

Error persists after rotating the secret: Allow up to 60 seconds for the new secret to propagate across Brightline authorization servers before retrying. Clock skew causes repeated expiry errors: The Brightline auth server rejects tokens if your server clock differs by more than 5 minutes; synchronize your system clock using NTP. Scope expansion not reflected after approval: You must request a new token after approval — existing tokens do not inherit newly granted scopes automatically. If none of these steps resolve the issue, open a support ticket from the Portal under Help > Contact Partner Support and include the X-Request-ID header value from the failed response. For guidance on idempotency when retrying failed requests, see How Do Idempotency Keys Behave When a Partner API Request Fails or Is Retried.
